# 메시지 브로커 비교 및 라이선스 분석

납품용 솔루션 도입을 고려하여 라이선스 안전성과 운영 편의성을 중점으로 분석한 자료입니다.

## 1. 분석 대상

| 브로커 | 주요 특징 | 라이선스 | 납품 적합성 | 비고 |
| :--- | :--- | :--- | :--- | :--- |
| **Apache Kafka** | 높은 처리량, 로그 중심, 사실상의 표준 | Apache 2.0 | ⭐⭐⭐⭐⭐ | 운영 복잡도가 높음 (KRaft 모드 권장) |
| **RabbitMQ** | 복잡한 라우팅, 신뢰성, AMQP 표준 | MPL 2.0 | ⭐⭐⭐⭐⭐ | 전통적인 메시지 큐 방식에 최적 |
| **NATS JetStream** | 초경량, 고성능, 단일 바이너리, K8s 친화적 | Apache 2.0 | ⭐⭐⭐⭐⭐ | **강력 추천.** 운영 비용이 가장 낮음 |
| **Apache Pulsar** | 컴퓨팅/스토리지 분리, 멀티 테넌시 | Apache 2.0 | ⭐⭐⭐⭐ | 기능은 강력하나 아키텍처가 복잡함 |
| **Redpanda** | Kafka 호환, Zookeeper 제거, 단일 바이너리 | BSL (Source Available) | ⭐⭐⭐ | 라이선스 검토 필수 (클라우드 서비스 제공 금지 조항 등) |
| **Redis (Valkey)** | 인메모리 속도, Stream 자료구조 | BSD 3-Clause (Valkey) | ⭐⭐⭐⭐ | 메시지 영속성(Persistence) 설정 주의 필요. **Redis 대신 Valkey 사용 권장** |

## 2. 상세 추천

### 🥇 NATS JetStream (강력 추천)
- **이유:** Go 언어로 작성되어 매우 가볍고(Docker 이미지 사이즈 작음), 설정이 간편합니다. 스트림(Kafka 스타일)과 큐(RabbitMQ 스타일) 기능을 모두 지원합니다. 납품 시 리소스 제약이 있는 환경에서도 잘 동작합니다.

### 🥈 Apache Kafka
- **이유:** 가장 널리 쓰이는 표준이므로 개발자 수급이 쉽고 레퍼런스가 많습니다. 대용량 처리가 필수적인 경우 선택합니다.

### 🥉 RabbitMQ
- **이유:** 메시지 순서 보장이나 복잡한 라우팅 로직이 비즈니스 로직의 핵심이라면 가장 안정적인 선택입니다.

## 3. 라이선스 주의사항 (Redis vs Valkey)
Redis는 최근 라이선스를 변경하여 상용 서비스 제공 시 제약이 생겼습니다. 납품용 솔루션이 지속 가능한 오픈소스 생태계에 있기를 원한다면, Linux Foundation에서 포크하여 관리 중인 **Valkey**를 사용하는 것을 권장합니다. 본 프로젝트의 `redis` 폴더에서는 호환성을 위해 Valkey를 기준으로 테스트하는 것을 제안합니다.
